# AI — Gemini Features, Credit Systems & TTS

> **Agent workflow:** read this BEFORE touching any AI generation route, credit/limit logic, `lib/ai/*`, analytics chat, or TTS. Update this doc in the same change whenever you alter behavior described here. Index: [README.md](README.md).

**Last verified:** 2026-07-12 (commit `7c31a96`).

## Purpose & scope

Every AI-powered feature, the credit/limit systems that meter them, and the TTS route.

### Provider switch (2026-10-22, Claude added 2026-10-30) — Gemini, DeepSeek or Claude, ONE file

- **[lib/ai/models.ts](../lib/ai/models.ts)** is the only place a provider or model is named: `AI_PROVIDER` (`'gemini' | 'deepseek' | 'claude'`, switches everything), `AI_MODELS` (each provider's default model), `CLAUDE_EFFORT` (Claude's thinking depth, `'medium'`), and `AI_FEATURES` — per feature (`questions`, `images`, `analytics`, `ielts`) a `{ provider, model? }`: `{ provider: AI_PROVIDER }` follows the switch, an explicit provider/model pins that feature. **As of 2026-10-30: `AI_PROVIDER = 'claude'` (`claude-sonnet-5-5`), DeepSeek default `deepseek-v4-pro`, Gemini default `gemini-3.5-flash`, and `images` follows the switch (so also `claude-sonnet-5-5`)** — every Claude model reads images, but DeepSeek v4-pro cannot: ⚠️ if `AI_PROVIDER` goes back to `'deepseek'`, pin `images` to `{ provider: 'gemini', model: 'gemini-3.5-flash' }` again. Claude accepts only JPEG/PNG/GIF/WebP; the by_image page compresses uploads but keeps their original type. `aiModelFor(feature)` is also what pages save as `metadata.aiModel` (and IELTS as `aiEstimate.model`). Browser-safe (no keys).
- **[lib/ai/generate.ts](../lib/ai/generate.ts)** (server only) is the only code that calls an AI: `generateJson({feature, prompt, temperature, schema, images?})` and `generateChat({feature, system, history, message})`. Keys: `GEMINI_API_KEY` / `DEEPSEEK_API_KEY` / `ANTHROPIC_API_KEY` in `.env.local` (missing → `AiError('NO_KEY')`).
  - **Claude** (`@anthropic-ai/sdk`, streamed via `beta.messages.stream(...).finalMessage()`, `max_tokens: 32000`): structured outputs (`output_config.format: json_schema`) enforce the JSON — the Gemini schema is converted by `toJsonSchema` (lowercased types, `additionalProperties: false` on every object, `nullable` → `[type,'null']`) and wrapped as `{data: …}` because the root must be an object. **`temperature` is NOT sent** (current Claude models / API version `2026-10-21` reject it with 400) — the per-route temperatures are ignored on Claude; `output_config.effort = CLAUDE_EFFORT` is the knob. Thinking is left adaptive (omitted). On `claude-sonnet-5-5` / `opus-5-5` / `opus-5` / `fable-5-1` the request opts into `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) so a safety decline is retried server-side; a final `stop_reason: 'refusal'` → `SAFETY`, `max_tokens` → `TRUNCATED`, SDK `APIError` → `HTTP`. Images go as base64 `image` blocks before the prompt. Chat: `model` turns → `assistant`, empty turns dropped, and a short user turn is prepended when history starts with the AI's summary (Claude requires a user turn first).
  - **Gemini:** the same REST request every route sent before (`responseSchema` enforces the JSON). **Busy fallback:** if a feature's own model (e.g. `gemini-3.5-flash` for images) answers 503 (overloaded — seen on 3 of 4 tries on 2026-10-27) or 429, the call is retried once on `AI_MODELS.gemini`; other errors are not retried. The saved `aiModel` label still names the feature's model.
  - **DeepSeek** (`https://api.deepseek.com/chat/completions`, Bearer key): `response_format: {type:'json_object'}` has **no schema enforcement**, so a system message carries an example + the Gemini schema and asks for `{"data": …}` (unwrapped; an array answer missing the wrapper is recovered). `thinking: {type:'disabled'}` (thinking ignores `temperature` and is slower), `max_tokens: 16000` (the 8K default can truncate a 30-question set). Images go as `image_url` data-URL parts — `deepseek-flash` reads images, `deepseek-v4-pro` does NOT (don't put it on `images`). Chat history `model` turns map to `assistant`.
  - Errors: `AiError` codes `NO_KEY` / `SAFETY` / `EMPTY` / `TRUNCATED` / `HTTP` (the provider's message). The prompt text is passed through unchanged on both providers.
- ⚠️ **The AI sometimes leaves math bare** (`\frac{4}{8}` with no `$…$`, mostly on short options) even though every prompt asks for `$`. LatexRenderer only renders inside delimiters, so it showed raw. [lib/ai/fixMath.ts](../lib/ai/fixMath.ts) wraps bare LaTeX (whole string if it is only math, else each math run; collapses an over-escaped `\\frac`; leaves text with `$`/`\(` alone). Applied via `cleanMcqItems` in every MCQ route (create/ai, by_user_input, by_image, maktab, ixtisos) and in the games route; bsb-chsb (mixed types) is NOT covered yet.
- ⚠️ Never call `generativelanguage.googleapis.com` / `api.deepseek.com` / the Anthropic SDK or hard-code a model name anywhere else.
- ⚠️ Claude is wired but **not yet run against the real API** (2026-10-30: request shape checked offline against the SDK with a faked stream). Needs `ANTHROPIC_API_KEY` in `.env.local` — without it every AI flow fails with `NO_KEY`, since Claude is now the active provider. The `@google/generative-ai` SDK is no longer used (still in package.json).
- ⚠️ DeepSeek is wired but **not yet run against the real API** (no `DEEPSEEK_API_KEY` as of 2026-10-22; request + parsing checked against a faked reply). Before switching, add the key and re-run the question quality checks.

## The THREE credit systems (know which one a flow uses)

### A — Daily (`lib/ai/aiLimitsHelper.ts` → `consumeAiCredits`) — **DEAD CODE**
Fields on `users/{uid}`: `aiDailyQuestionLimit` (fallback 50), `aiQuestionUsedToday`, `aiQuestionLastResetDate`; lazy reset by `Asia/Tashkent` date. **Nothing calls `consumeAiCredits`, and `hooks/useAiLimits.ts` is never imported.** The fields survive only as legacy fallbacks in admin UIs (`app/admin/teachers/page.tsx`, `MembershipTab.tsx`). Do not build on this system; prefer B.

### B — Monthly SaaS (`lib/ai/featureGatekeeper.ts`) — **LIVE, used by all 6 teacher create routes**
- Fields on `users/{uid}`: `includedFeatures[]`, `currentLimits.monthlyAiQuestions` (fallback 100), `usage.aiQuestionsUsed`, `usage.aiLimitResetDate` (display only).
- `checkUserPermission(userId, featureKey, requestedCount)`: feature-lock check → `FEATURE_LOCKED`; `monthlyAiQuestions >= 5000` means **unlimited**; else over-limit → `LIMIT_REACHED`.
- `deductMonthlyAiCredits(userId, actualCount)`: `FieldValue.increment` merge; no-op if ≤ 0.
- Plans (`plansData.ts`): Free 100 / mid 1000 / top 5000 (=unlimited). Admin edits + usage reset: `app/admin/membership/`, `admin/teachers/[id]/_components/MembershipTab.tsx`. UI display: `hooks/useMonthlyLimit.ts`, `teacher/subscription/page.tsx`, teacher layout.
- `featureKey: null` = a flow open to every plan (only the monthly limit applies) — used by the games route.
- **Pattern (mandatory for new AI flows): check permission → call Gemini → deduct only the actual generated count** so failed generations don't burn credits. All 6 routes follow the check/deduct-actual shape, **but only `by_image` calls the real gatekeeper** — the other 5 inline a copy of the limit math (no feature-lock, drift risk). When touching those routes, prefer migrating them to `checkUserPermission`.

### C — Per-day server counter `ai_usage/{userId}_{YYYY-MM-DD}` — **LIVE, analyze route only**
- Written/read ONLY by `app/api/analyze/route.ts`: reads `count`, 429s at limit, increments +1 per request (`{count, userId, date}` merge, `FieldValue.increment`).
- **The route is authenticated.** It requires `Authorization: Bearer <idToken>`; the **uid comes from the verified token, never from the body**. It was previously unauthenticated and took `userId` from the request body — i.e. an open Gemini proxy that could also spend another user's quota.
- **The limit is server-owned**: `AI_ANALYZE_DAILY_LIMIT` env (default 15). It used to arrive as `dailyLimit` in the request body (from Remote Config), so the caller chose their own cap and the check was decorative. ⚠️ Never reintroduce a client-supplied limit.
- Date key is **UTC** (`toISOString().split('T')[0]`), unlike A/B which use Asia/Tashkent.
- Uses the **Admin SDK** (`adminDb`), like every other AI route. Firestore rules for `ai_usage` are therefore `read, write: if false` — no client may touch the counter. (Before: client SDK in a server route + world-open rules, so anyone could zero their own usage.)

## TTS — `app/api/tts/route.ts`

`msedge-tts` (Azure neural), output MP3 24kHz/48kbit mono. Voice hardcoded `uz-UZ-SardorNeural` — the `voice` param is ignored (female `MadinaNeural` commented out). Writes a temp file via `tts.toFile(os.tmpdir(), ...)`, reads + unlinks, returns the buffer. `export const dynamic = 'force-dynamic'` is **required** (native module + fs); any new route using native modules/fs must do the same. No auth, no rate limit, no credit check. Bottom half of the file is a commented-out Muxlisa implementation.

## Invariants & traps

- ⚠️ **Worked solutions + answer check (2026-10-31).** Every AI generator's `e` is now a worked solution, not a ≤15-word hint: `SOLUTION_RULE` in [lib/ai/questionPrompts.ts](../lib/ai/questionPrompts.ts) (≤4 numbered steps, ~50 words, ONE line because LatexRenderer collapses line breaks, math in `$…$`, ends with `Javob: X`). **The schema order is `q, o, e, a`** — the solution is written BEFORE the answer index so the answer comes from the solution; `MCQ_SCHEMA` carries `propertyOrdering` because Gemini otherwise sorts keys alphabetically (`a` first). Don't reorder it. `checkMcqItems(items, language)` drops a question whose `Javob` letter ≠ `a` (logged `AI question dropped`), keeps one with no `Javob` mark (can't check), and rewrites the tail to `Javob/Ответ/Answer: <option text>` — never a letter, because options are shuffled later. [lib/ai/generateMcqs.ts](../lib/ai/generateMcqs.ts) (`generateMcqs({build, count, language})`) = generate → `cleanMcqItems` → `checkMcqItems` → if short, ONE retry for just the missing number (a retry failure keeps the first batch). Used by create `ai`/`by_user_input`/`ixtisos`/`maktab` and the games route; `by_image` does the same inline (its schema wraps `items` in `{error, items}`); `bsb-chsb` uses the rule for every type (open-ended model answer also ≤4 steps/~50 words, rubric still ≤10 words) and only DROPS mismatched MCQs (no retry — the type distribution is fixed). Credits are deducted on what is returned, so dropped questions are never charged. Output is ~3–4K tokens more per 30-question set.
- **Showing solutions (2026-10-31):** [lib/solutionSteps.ts](../lib/solutionSteps.ts) `splitSolution(text)` splits a stored one-line solution into `{lead, steps[], answer{label,value}}` (step markers `1) 2) …` must run in order, only outside `$…$`; last `Javob:/Ответ:/Answer:` after the last step = answer; returns null for plain explanations). [components/SolutionSteps.tsx](../components/SolutionSteps.tsx) renders it as numbered badges + an answer pill, kit-neutral (tints are `color-mix` of `currentColor`), with a `render` prop for the screen's own math renderer (FormattedText / MathText / LatexRenderer). It renders `<div>`s — never inside `<p>`. Used on: teacher create previews (by_image, by_user_input, maktab, ixtisos, DraftQuestionCard, CartItem), my_questions info modal, student test results, raschmodel review + topic, My Mistakes, SatReview. Display-only — stored data unchanged, old saved solutions get the look too.
- ⚠️ **The generator prompts live in ONE file: [lib/ai/questionPrompts.ts](../lib/ai/questionPrompts.ts)** (`freePromptQuestions`, `dtmQuestions`, `ixtisosQuestions`, `maktabQuestions` → `{prompt, temperature}`), moved verbatim out of the 4 create routes on 2026-10-21 (byte-identical, checked on 16 inputs covering every subject branch). The create routes and the games route both call them — edit a prompt there, never inline it again. The Maktab local bank lookup is likewise shared: [lib/ai/maktabBank.ts](../lib/ai/maktabBank.ts). The create routes keep their own auth/credit/response code (still the body-`userId` pattern).
- ⚠️ The Maktab banks currently answer **402 Payment Required** from Storage (Blaze needed), so the bank branch never hits — see [GAMES.md](GAMES.md) known issues.

- Unlimited threshold `>= 5000` is duplicated in ~8 places (gatekeeper, `useMonthlyLimit`, and inline in 5 routes) — changing plan numbers requires touching all of them.
- Check→deduct is **non-atomic** everywhere (read then `increment`) — concurrent requests can overshoot limits. Accepted for now; don't assume the counters are exact.
- The `maktab` local-DB branch deducts monthly AI credits even when questions come from the static bank (charging AI credits for non-AI content) — known quirk, decide deliberately before "fixing".
- `deductMonthlyAiCredits` failures are swallowed (returns false, callers ignore) — no refund path.
- Analytics (System C) usage is invisible in the subscription/admin UIs, which surface only System B.
- Timezone: A/B use Asia/Tashkent day boundaries; C uses UTC.

## How to verify changes

`npm run dev`; exercise a teacher create flow and watch `users/{uid}.usage.aiQuestionsUsed` increment by the actual generated count (and NOT increment on generation failure); for analytics, watch `ai_usage/{uid}_{date}`. Requires the key of the active provider in `.env.local` (`GEMINI_API_KEY`, `DEEPSEEK_API_KEY` or `ANTHROPIC_API_KEY`). After switching `AI_PROVIDER`, run one flow per feature: a create page (questions), by_image (images), analytics chat, IELTS estimate — and check a saved question's `metadata.aiModel` names the new model.
