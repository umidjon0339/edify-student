# DATA MODEL — Firestore Collection Reference

> **Agent workflow:** read this BEFORE adding/changing any Firestore read or write, and update it in the same change when you add a collection, field, or index. Domain docs explain the flows; this file is the collection-by-collection truth. Index of docs: [README.md](README.md).

**Last verified:** 2026-07-30 (`milliy_quizzes` + `milliy_quiz_results` added); 2026-07-29 (`teacher_rasch_results.items` added); 2026-07-28 (`teacher_rasch_quizzes` + `teacher_rasch_results` added); everything else 2026-07-12 (commit `7c31a96`) — every entry below was verified against actual reads/writes in code, not inferred.

Conventions: **Writer** says which SDK writes it (client = browser SDK under security rules; admin = Admin SDK in API routes, bypasses rules). ⚠️ marks traps. Timestamps are **inconsistent across the codebase** — see the table at the bottom; always check the specific writer before comparing/ordering.

## Accounts & identity

- **`users/{uid}`** — master doc for all roles; doc ID = Auth uid. Writer: client (signup flows, profile, XP transactions), admin UIs via god-mode, `deductMonthlyAiCredits` (admin SDK). ⚠️ **Privileged fields are denied to the client on BOTH create and update** — `role`, `centerId`, `subscription`, `currentLimits`, `includedFeatures`, `usage`, `verifiedTeacher`, `isActive`. Never treat `role`/`centerId` as an authorization source; prove ownership via `centers.ownerUid`. Full table + rationale in [AUTH.md](AUTH.md). Union of role fields:
  - Identity: `email`, `username` (**always lowercased**), `displayName`, `role` ∈ student|teacher|manager|**director|accountant** (the last two are back-office roles written ONLY by the Admin SDK and are a **redirect hint, never an authorization source** — [OFFICE.md](OFFICE.md); the rules' create allowlist still admits only the first three), `phone`, `birthDate`, `gender`, `institution`, `location{country,region,district}`, `photoURL`, `bio`, `createdAt` (ISO string). Moderation: `isActive`.
  - Student gamification: `totalXP`, `currentStreak`, `level` (⚠️ written 1 at signup, never updated — levels are derived `floor(totalXP/1000)+1`), `lastActiveDate` (⚠️ live field; the `lastStudyDate` in `UserProfile` interface is dead), `dailyHistory{YYYY-MM-DD: xp}` (UTC keys, trimmed to 30), `dailyGoal`, `dailyGoalRewardedOn (YYYY-MM-DD — the UTC day the +25 daily-goal bonus was paid)`, `gamesDaily{date, xp}` (per-UTC-day games-XP cap tracker), `recentActivity[]`, `progress{...}` (⚠️ dead — writer is unwired). All gamification fields are written ONLY through `lib/xp.ts::applyUserXp`.
  - Teacher: `subject`, `grade:'Teacher'`, `verifiedTeacher`, `experience`; `activeClassCount`/`totalStudents`/`customTestCount` are ⚠️ Cloud-Function-generated (functions not in repo — may be absent).
  - Teacher SaaS: `subscription{planId,billingCycle,status,expiresAt}`, `currentLimits{maxClasses,maxStudents,monthlyAiQuestions}`, `includedFeatures[]`, `usage{aiQuestionsUsed,aiLimitResetDate}` (see [AI.md](AI.md)). Legacy daily fields `aiDailyQuestionLimit`/`aiQuestionUsedToday`/`aiQuestionLastResetDate` are ⚠️ dead (no enforcement).
  - Manager: `centerId`. Social: `followersCount`/`followingCount` (rules allow any authed user ±1 delta on these two only).
  - Center-created teacher accounts (2026-07-15): `accountType:'center-managed'` + `centerId` — written by `/api/manager/teachers/create` (Admin SDK). Marks accounts whose email is synthetic (`f.surname@edify.uz`, shared fixed domain, no real inbox) and whose password is manager-held; the password-reset branch of `/api/manager/teachers/[uid]` requires this flag. Absent on self-signup accounts.
  - Queried by: `role ==`, `email ==`, `orderBy totalStudents desc` (explore).
- **`users/{uid}/private/contact`** — `{email, phone}`. Rules: **owner-only** (`isOwner`). The parent `users/{uid}` doc is readable by every signed-in user and Firestore has no field-level read rules, so contact details cannot live on it — anyone could sign up and dump every user's email and phone in one query. Teachers/managers who legitimately need them go through `POST /api/directory/contact` (relationship proven with the Admin SDK); an email→account lookup is `POST /api/directory/lookup`. ⚠️ **Never write `email`/`phone` back onto the parent doc** — use `setOwnContact()` in `lib/directory.ts`. Migration status + DEPLOY-2 blockers: [AUTH.md](AUTH.md).
- **`users/{uid}/following/{targetUid}`**, **`users/{uid}/followers/{followerUid}`** — social edges, `{followedAt}`. Writer: client (`lib/social.ts`, atomic batch with counters + notification).
- **`usernames/{lowercaseUsername}`** — uniqueness reservation, `{uid}`. Immutable (rules: update false). Writer: client signup batches, admin center-create route. Read by Admin SDK in `/api/auth/login` + `/api/auth/reset-password` to resolve username→uid for username login (see [AUTH.md](AUTH.md)) — never add emails here; the collection is public-read.

## Question banks (three separate stores — never mix)

- **`questions1/{autoId}`** — global master bank, bulk-imported externally; since 2026-10-29 the super admin also adds/edits it at `/admin/question-bank` through `/api/admin/questions1` (the ONLY in-repo writer — client rules stay `write: false`; contract in [ADMIN.md](ADMIN.md) "Question bank"). Admin-written docs carry the same shape plus additive `addedBy`/`source:'admin'` (`editedAt`/`editedBy` on edit); `uploadedAt` is written in whatever type the existing bank uses (read from a sibling doc — the import script that created the bank is not in this repo). Consumers: `quizService.fetchQuestions` (`app/teacher/create/database/`) **and the student Milliy sertifikat exam** ([lib/Examquestions.ts](../lib/Examquestions.ts), `rand`-sampled), which fills **exam slots 1–32** (the Y-1 sections). Query traps: `topicId` string **NOT padded**; `chapterId`/`subtopicId` strings **zero-padded to 2**; `difficultyId` **number** 1/2/3; `subjectId` param exists but is **ignored**; `orderBy uploadedAt desc` (needs composite index). Content: `question{uz,ru,en}`, `options{A..D}`, `answer`.
- **`teacher_questions/{id}`** — teacher-owned bank, doc ID `tq_${autoId}`, **doc key === `id` field** (the old AI-path mismatch is fixed). **Holds TWO shapes and always will — read [QUESTIONS.md](QUESTIONS.md) before touching it.**
  - **v1 (everything written from 2026-07-14 on, by every creator)** — the canonical schema in `types/question.ts`: `schemaVersion:1`, `status`, `type` (mcq/open/…), `answerMode`, `rand` (uniform [0,1) for the exam's per-student sampling), `subject|topic|subtopic|chapter:{id,name}`, `difficulty:{id,name,rasch,estimatedAbility}`, `points`, `estimatedTime`, `question{uz,ru,en}`, `image{hasImage,storagePath,downloadUrl,w,h}`, `options:[{id,text{uz,ru,en},image}]` (**an ARRAY**, up to A–F, each option may carry its own image), `correctAnswer:{value,acceptedAnswers,caseSensitive}` (`value` = letter | letter[] | typed text), `parts:[{id,prompt,type,options,correctAnswer,points,explanation}]` (**blocks only** — one stem + N sub-questions in ONE doc; `shared_options` parts keep `options:[]` and read the block's pool, so it is stored once. A student's answer is ONE `attempts.answers[qId]` entry = `{[partId]: value}`. See [QUESTIONS.md](QUESTIONS.md)), `solutions:[{method,steps{uz,ru,en}[],finalAnswer}]`, `hint`, `explanation`, `references[]`, `tags[]`, `curriculum[]`, `language[]`, `adaptive`, `metadata:{creatorId,creatorName,creationMethod,aiModel,verified,reviewedBy,createdAt,updatedAt,publishedAt,deleted,correctedBy,correctedById,correctedAt}`  (⚠️ `correctedBy` = who last EDITED it, `creatorName` = who originally wrote it — never conflate them).
  - **legacy (pre-existing docs — never migrated)** — flat: `options:{A..D:{uz,ru,en}}` map, `answer:'B'` letter, `difficulty:'easy'` string, `track`, `number`, `uploadedAt`.
  - ⚠️ **Flat query mirrors on v1 docs — `creatorId`, `creationMethod`, `difficultyId`, `createdAt` — are duplicated from the nested values on purpose.** Firestore can't filter across two shapes and an OR-query would double the reads, so these four (the same names legacy docs use) let ONE query + ONE index serve both eras. **Never filter on `difficulty.name` or `metadata.creatorId`**, and never `where('difficulty','==','easy')` — that silently returns zero v1 docs; use `difficultyId ==` instead.
  - Every reader goes through `normalizeQuestion()` ([lib/questionSchema.ts](../lib/questionSchema.ts)); every writer through `toQuestionV1()`. Images: Storage `teacher_questions/{uid}/{questionId}_{slot}_{ts}{ext}`; deleting a question must delete them (`deleteQuestion`). Queried by `creatorId ==` (+ `difficultyId ==` / `creationMethod in [...]`) `orderBy createdAt desc`.
  - **Also read by the student Milliy sertifikat exam** ([lib/ExamTeacher.ts](../lib/ExamTeacher.ts)) to fill **exam slots 33–45** — a **per-student random draw** via the `rand` field (uniform [0,1), written by `toQuestionV1` on every save; backfilled onto the pre-existing bank by `npm run backfill:rand`), the SAME threshold sampling questions1 uses. `where('subject.id','==','algebra'|'geometriya') where('rand', >=|<, Math.random()) orderBy rand limit 80` per subject (new `subject.id`+`rand` index), so two students get different questions. ⚠️ **Legacy teacher docs have no `rand`** and are invisible to that query — the sampler then falls back to a fixed `subject.id`+`createdAt` page (identical for everyone), which is exactly what the backfill fixes. Any teacher, any status. If the teacher bank can't fill a section, the shortfall is **topped up from questions1** (same chapters + test-type difficulty band) so the paper is always 45 questions. The two taxonomies are a verified 1:1 mirror, so a doc's topic slug is bridged by position to the questions1 `topicId`/`chapterId`/`subtopicId` the RASCH pipeline groups on. **Block counting rule:** a `shared_options` block is ONE grouped card that counts as one exam question PER sub-question (pool printed once, scored per part); a `multi_part` block is ONE card / ONE slot (graded all-parts-correct). See [QUESTIONS.md](QUESTIONS.md).
- **`question_stats/{questionId}`** — ⚠️ **declared in `types/question.ts`, written by nobody.** Statistics are kept OUT of the question doc (content is written once, stats churn on every answer). Per-answer writes would multiply Firestore cost, so this is meant for an offline/batched aggregation — see [QUESTIONS.md](QUESTIONS.md) before wiring anything to it.
- **`reported_questions/{questionId}`** — doc ID = reported question id (dedupes). `reasons[]`/`reportedBy[]` (arrayUnion), `reportCount` (increment), `status`.

## Classes & center management

- **`classes/{classId}`** — teacher- or center-created class. Writer: client. `{title, description, joinCode (⚠️ random, no uniqueness check), teacherId, teacherName, studentIds[], studentCount (⚠️ always 0, never maintained — use studentIds.length), isLocked, schedule[{dayOfWeek,startTime,endTime,roomId?,roomName?}], createdAt (Timestamp), monthlyFee? (int so'm, finance), centerId? (center groups only), ieltsGroupId? (center IELTS groups only — id of the linked `ielts_groups` twin; roster writes must mirror it, see [IELTS.md](IELTS.md)), schoolClassId? (2026-09-14, back-link to a `school_classes` doc when this class is a "subject" slot — see below and [MANAGER.md](MANAGER.md)), schoolClassName? (denormalized `school_classes.displayName`, e.g. "5-A", display-only)}`.
  🟢 **`centerId` IS the center-membership anchor (2026-07-15)** — a class belongs to a center iff `centerId` matches; a linked teacher's personal groups (no `centerId`) stay out (see [MANAGER.md](MANAGER.md)). Rules: stamping `centerId` at create requires manager/teacher of that center; `centerId` is **immutable client-side** afterwards. Queried by `centerId ==` (manager panel, finance, admin), `teacherId ==` (teacher panel), `joinCode ==`, `studentIds array-contains`, `schoolClassId ==` (a School Class's subjects). Rules: the `studentIds`-only self-diff branch allows own-uid add/remove only; on center groups (`centerId != ''`) it is leave-only, and the teacher cannot write the class doc at all — roster/settings/delete are manager-only (2026-07-19, see [MANAGER.md](MANAGER.md)/[TEACHER.md](TEACHER.md)).
  - `.../assignments/{autoId}` — `{testId→custom_tests, testTitle, questionCount, duration|null, resultsVisibility, openAt, dueAt|null, assignedTo:'all'|uid[], allowedAttempts (0=∞), completedBy[] (arrayUnion), status:'active' (static), teacherId, createdAt}`. `duration`/`resultsVisibility` are denormalized from the test by `AssignTestModal` (2026-07-20) — **absent on older docs**, so readers must treat `undefined` as unknown, not as "no limit". `resultsVisibility:'after_due'` requires a `dueAt` (modal-enforced). ⚠️ Read rule contains `|| true` — world-readable to authed users.
  - `.../exams/{autoId}` — `{testId→bsb_chsb_tests, title, assessmentType, examDate, durationMinutes, hideResults, submittedStudentIds[], status:'scheduled', teacherId, createdAt}`.
  - `.../materials/{autoId}` — `{title, description, topicId, fileUrl, storagePath|null, isExternal, externalUrl, fileType/Size/Extension, isVisible, isArchived, orderIndex (Date.now()), viewCount/downloadCount, uploaderId, createdAt}`.
  - `.../requests/{autoId | studentUid}` — ⚠️ **two shapes**: JoinClassModal `addDoc {studentId, studentName, studentUsername, photoURL, createdAt}` vs explore `setDoc(/{uid}) {..., status:'pending'}`. Tolerate both.
  - `.../leaderboard/{uid}` — per-class XP mirror `{xp: increment, lastActive, ...}`; written by assignment submits only (⚠️ not by checkers).
- **`centers/{centerId}`** — `{id, name, slug, ownerUid, size, status ('pending'|'active'|'suspended'; missing=pending), subscription{plan,validUntil} (display-only, unenforced), createdAt (ISO), adminStatus? ('active'|'archived'), adminNotes?}`. Writers: client signup (status forced 'pending' by rules), admin god-mode client writes (status/name/notes), admin API (born 'active').
- **`center_teachers/{teacherUid}`** — doc ID **must equal** teacher uid (one center per teacher). `{centerId, teacherId, teacherName, teacherEmail, addedAt (serverTimestamp), salary?}`. Queried by `centerId ==`. This link is the center-membership anchor.
- **`center_students/{centerId}_{studentId}`** — 🟢 center student roster (2026-07-15). Doc id composition **rules-enforced** (`centerId + '_' + studentId`). `{centerId, studentId, studentName, source ('created'|'linked'|'enrolled'), addedAt (serverTimestamp)}`. A student may be in SEVERAL centers (one link per center) and in a center with no classes. Writers: manager client (add-existing, lazy backfill, group enroll) + `/api/manager/students/create`. Queried by `centerId ==` (manager roster) and `studentId ==` (student's own centers). Reads: student themselves, center manager, center teachers.
- **`school_classes/{centerId}_{grade}_{section}`** — 🟢 School Classes (2026-09-14, [MANAGER.md](MANAGER.md)). A grade-level container ("5-A") a manager creates to group several `classes` docs ("subjects") under one shared roster. Doc id `${centerId}_${grade}_${section}` — rules-enforced, gives free uniqueness (same idiom as `center_students` above). `{centerId, grade (string "1".."11" — kept as a string so the doc-id concatenation trick works in rules), section (string, manager-entered, trimmed+uppercased), displayName (`${grade}-${section}`), studentIds[] (ROSTER SOURCE OF TRUTH), createdAt, createdBy}`. `centerId`/`grade`/`section` are **immutable after create** (delete-and-recreate if wrong — no rename). Queried by `centerId ==`. Writers: manager client only (`services/schoolClassService.ts`), gated `isActiveCenterManager`; create uses a Firestore transaction (not a plain getDoc-then-setDoc) to avoid a TOCTOU race, since Firestore rules evaluate a `setDoc` on an already-existing doc as `update`, never `create`. ⚠️ **Roster invariant**: every write to `studentIds` must update this doc **and** every `classes` doc with matching `schoolClassId` in one batch (`syncSchoolClassRoster`) — the same "keep the mirror in sync" contract as the `ielts_groups` twin above, just N-way instead of 1:1. Delete requires the manager to first remove every linked subject (checked client-side, not rules-enforced).
- **`center_student_credentials/{studentUid}`** — 🔐 manager-visible password for **center-created** student accounts; identical contract to `center_teacher_credentials` below (API-only writes, owning-center manager reads, the student cannot read it).
- **`center_teacher_credentials/{teacherUid}`** — 🔐 the manager-visible password for **center-created** teacher accounts. `{centerId, teacherId, password (plaintext — deliberate: the manager is the account's recovery path; synthetic emails receive no reset mail), updatedAt (serverTimestamp)}`. Writer: **Admin SDK only** (`/api/manager/teachers/create` + password-reset branch of `/api/manager/teachers/[uid]`); rules `write: false`, reads manager-of-center only (`get` also allows missing doc; not readable by the teacher). Exists ⇔ the account is center-managed. See [MANAGER.md](MANAGER.md).
- **`center_staff/{uid}`** — 🟢 office-staff link (2026-09-15, [OFFICE.md](OFFICE.md)). Doc ID **must equal** the staff uid — that is what makes `isCenterOffice()` / `requireCenterOffice()` trustworthy (the `center_teachers` idiom). `{uid, centerId, staffRole ('director'|'accountant'), name, email, username, createdAt (serverTimestamp), createdBy (super-admin uid)}`. ⚠️ **Not related to `center_staff_attendance` below despite the name** — this is back-office ROLES, that is teachers' daily attendance. Writer: **Admin SDK only** (`/api/admin/centers/{id}/staff`); rules `write: if false` for every client, **the center manager included**. Reads: the staff member's own doc, plus the center's manager (`centerId ==` filtered list). Queried by `centerId ==`.
- **`center_staff_credentials/{uid}`** — 🔐 the super-admin-held password for an office account. `{uid, centerId, password (plaintext — the synthetic `f.surname@edify.uz` email has no inbox, so the admin is the only recovery path), updatedAt}`. Rules: **`read, write: if false`** — denied to every client, manager included; only god mode / the Admin SDK reach it. Stricter than `center_teacher_credentials` on purpose, because these accounts are provisioned by the admin, not the manager.
- **`center_attendance/{classId}_{YYYY-MM-DD}`** — see [ATTENDANCE.md](ATTENDANCE.md). `{id, classId, centerId, date, weekday, lessonStatus, records{uid: {status,method,markedBy,markedAt(Timestamp.now()),note?,confidence?}}, recordedBy, createdAt/updatedAt}`. Writers: attendance grid + `checkInService` (client).
- **`center_staff_attendance/{staffUid}_{date}`** — staff/teacher daily attendance; written by `components/attendance/StaffAttendanceGrid.tsx` (client `setDoc`; clearing a cell deletes the doc), read by `attendanceService.fetchStaffSessions`, deleted by admin cascade. See [ATTENDANCE.md](ATTENDANCE.md).
- **`center_attendance_summary`**, **`face_enrollments`** — see [ATTENDANCE.md](ATTENDANCE.md).
- **`rooms/{roomId}`** — see [ROOMS.md](ROOMS.md). `{centerId, name, capacity, color, features, building?, isActive, orderIndex, createdAt/updatedAt}`. Query `centerId == orderBy orderIndex`.
- **`center_finances/{financeId}`** — ⚠️ legacy: exists only in rules, no code reads/writes it. Do not build on it.

## Tests & submissions

- **`custom_tests/{autoId}`** — teacher practice tests; `{teacherId, teacherName?, title, track, subjectName..., questions[] (embedded), duration (0=∞), shuffle, resultsVisibility, accessCode, status, createdAt, questionCount}` — shape drifts by creator ([TEACHER.md](TEACHER.md)).
- **`teacher_rasch_quizzes/{rq_…}`** — a teacher-assembled **45-question Rasch paper** opened by a private 6-digit code; `{id, title, description, teacherId, teacherName, accessCode (6 DIGITS, a string — never parse it, `"048213"` loses its zero), questions[] (embedded `RaschQuizItem` snapshots), questionCount (exam SLOTS, not cards), durationMinutes, shuffle, showAnswers, status:'draft'|'published'|'closed', createdAt/updatedAt serverTimestamp}`. Index `teacherId`+`createdAt desc`. ⚠️ The embedded questions carry their correct answers and the collection is `read: if isAuth()` — the code is a sharing convenience, **not** a security boundary. ⚠️ `slotNumber`/`sectionLabel` are deliberately NOT stored (derived by `hydrateQuiz`); `sectionId` IS, and must be a real `EXAM_BLUEPRINT` id or the response is credited to the wrong dimension. See [RASCH_QUIZ.md](RASCH_QUIZ.md).
- **`teacher_rasch_results/{quizId}_{uid}`** — one sitting of the above; `{quizId, quizTitle, teacherId, studentId, studentName, correct, total, percent, durationSec, submittedAt (epoch ms number), examLang, topics: Record<TopicKey,TopicScore>, topicTheta?: Partial<Record<TopicKey,number>>, items?: Record<slotKey, 0|1>, theta}`. ⚠️ `topicTheta` is per-dimension ability in **logits** (not levels — `thetaToLevel` has been restretched once already), and a dimension the paper never touched is **absent**, never `0`. Optional: rows written before 2026-07-28 have none and render as "not measured" rather than being back-derived from the percentage. Deterministic ID ⇒ a retake **overwrites**, exactly like `attempts`. Read by the student or `teacherId`; **delete is denied to everyone**. Queried equality-only (`quizId ==` + `teacherId ==`), so it needs no composite index. Written alongside — never instead of — the student's own `RASCH_levels`/`RASCH_attempts` save. ⚠️ `items` (2026-07-29, optional) is the per-SLOT outcome map — `1` right, `0` wrong — keyed by `examSlotKeys` (`qid`, or `qid#partId` for each sub-question of a `shared_options` block), the SAME id `ItemResponse.id` carries. It is what makes the teacher's marks dynamic ([RASCH_QUIZ.md](RASCH_QUIZ.md)): the class solve rate per question is computed from the rows the results page already reads. Outcomes only — the answers themselves are still not stored. Rows without it are EXCLUDED from those statistics, never counted as wrong.
- **`milliy_quizzes/{ms_…}`** — a teacher-assembled **Milliy sertifikat SUBJECT paper** (biology + chemistry today; physics / English next), opened by a private 6-digit code; `{id, subject:'biologiya'|'kimyo'|'fizika'|'ingliz', title, description, teacherId, teacherName, accessCode (6 DIGITS, a string), questions[] (embedded `MilliyQuizItem` snapshots), questionCount (exam SLOTS, not cards), questionTarget (the TEACHER's declared length — **not** a national spec), durationMinutes, shuffle, showAnswers, status:'draft'|'published'|'closed', createdAt/updatedAt serverTimestamp}`. Index `teacherId`+`subject`+`createdAt desc`. ⚠️ **This is NOT where the maths paper lives** — that is `teacher_rasch_quizzes`, and only a maths sitting moves `RASCH_levels`. ⚠️ `accessCode` uniqueness is checked across **both** paper collections, because the student types one code into one box (`findPaperByCode`). ⚠️ Same leak as above: embedded questions carry their answers behind `read: if isAuth()`. ⚠️ `slotNumber`/`sectionLabel` are NOT stored (derived by `hydrateMilliyQuiz`); `sectionId` here is the question's own **topic slug**, not an `EXAM_BLUEPRINT` id. See [MILLIY_QUIZ.md](MILLIY_QUIZ.md).
- **`milliy_quiz_results/{quizId}_{uid}`** — one sitting of the above; `{quizId, quizTitle, subject, teacherId, studentId, studentName, correct, total, percent, durationSec, submittedAt (epoch ms number), examLang, items?: Record<slotKey, 0|1>, topics?: Record<topicSlug, {correct,total}>}`. ⚠️ **No `theta` and no `topicTheta`, deliberately** — there is no calibrated item difficulty or blueprint for these subjects, so an ability estimate would be a number with nothing behind it ([MILLIY_QUIZ.md](MILLIY_QUIZ.md)). `topics` is raw counts keyed by the question_topics **topic slug**, and a topic the paper never touched is **absent**, never `{0,0}`. `items` is the per-SLOT outcome map keyed by `examSlotKeys` (`qid`, or `qid#partId` per sub-question of a `shared_options` block) — outcomes only, never what was answered; rows without it are EXCLUDED from the solve-rate statistics, never counted as wrong. Deterministic ID ⇒ a retake **overwrites**. Read by the student or `teacherId`; **delete denied to everyone**. Queried equality-only, so no composite index. Exactly **one** write on submit (a maths sitting writes twice).
- **`sat_pool/{batchId}_{part}`** — 🟢 the SAT PRACTICE BANK (2026-10-31, [SAT_QUIZ.md](SAT_QUIZ.md) §practice bank). One teacher upload = one batch of CHUNK docs `{subject:'sat-matematika'|'sat-ingliz-tili', batchId, title, teacherId, teacherName, part, parts, count, items: SatQuizItem[] (< 700 KB, with `subtopic`), createdAt serverTimestamp}`. Read by any signed-in user (students load the subject's chunks to generate tests); create only by `users.role == 'teacher'` as themselves; never updated; deleted by the uploader. Queries equality-only (`subject ==`, `teacherId ==` [+ `batchId ==`]) — no composite index. Students' GENERATED tests are ordinary `sat_math_tests`/`sat_english_tests` docs they own (`teacherId` = student uid, id `satp_`/`satep_`, `practice: true`, `accessCode: ''`) — **shared since 2026-10-31**: listed to everyone via `practice == true` + `createdAt desc` (composite index on both collections); a result on a practice mock carries the SITTER's uid as `teacherId`; a teacher's copy is a new teacher-owned test with `sourceMockId`.
- **`bsb_chsb_tests/{autoId}`** — formal assessments; `{id, teacherId, teacherName, title, schoolType, assessmentType, grade, subject, scopesCovered, totalPoints, questionCount, difficultyTarget, questions[] (typed: mcq/true_false/short_answer/matching/open_ended with points/pairs/rubric), status, createdAt}`. Index teacherId+createdAt desc.
- **`attempts/{uid}_{assignmentId | examId}`** — ⚠️ **polymorphic; always branch on `type`**. Deterministic IDs mean retakes merge-overwrite (`attemptsTaken: increment`). Assignment shape vs exam shape in [STUDENT.md](STUDENT.md); exam docs overload `assignmentId` = examId; grading adds `manualScores`, `teacherScore`, `status:'graded'`, ⚠️ `autoScore` reset to 0 on grade save. 🟢 Exams with NO `open_ended` questions arrive **already graded from the student runner** in that exact shape (auto-release, 2026-07-20). The third "legacy practice" shape (`subtopicName`, `results[]`, `questionPath`) is **dead** — `historyService` has no consumers. Heavily queried: `userId ==`, `classId ==`, `assignmentId ==`/`in`, `type ==`, `orderBy submittedAt desc`.
  - ⚠️ **`score`/`totalQuestions` on an assignment attempt are POINTS, not question counts.** A question is worth `points` (which normalizes to 1 when absent, so a block-free test is byte-for-byte identical to the old correct-count), and a **block** is worth the sum of its parts with **partial credit**. `attempt.score / attempt.totalQuestions` stays a coherent percentage either way. Score with `gradeQuestion()` — never by counting `=== q.answer` matches.
  - ⚠️ **`answers[questionId]` is no longer always an option letter.** Since the v1 question schema it is `string` (letter, for mcq/true_false), `string[]` (letters, for `multiple_select`), **free text** (`open`/`numeric`), **or a `BlockAnswer` object** `{[partId]: value}` holding a whole block's response in ONE entry. Never compare it with `=== q.answer` — use `isAnswerCorrect(q, given)` from [lib/questionSchema.ts](../lib/questionSchema.ts), the single comparator the student runner, the results page and teacher-side review all share. See [QUESTIONS.md](QUESTIONS.md).

## IELTS (see [IELTS.md](IELTS.md) — full shapes in [lib/ielts/types.ts](../lib/ielts/types.ts))

- **`ielts_groups/{groupId}`** — `{title, targetBand, joinCode ('I-'+4–6 chars, unique via generateUniqueJoinCode), teacherId, teacherName, description, studentIds[], createdAt}` + **center-managed extras (2026-07-29, additive)**: `centerId?, classId?, managed?` — set ONLY by `POST /api/manager/ielts-groups` (Admin SDK), which creates the group as the twin of a `classes` doc (`classes.ieltsGroupId` back-link; timetable/attendance/finance ride the class). Read rule: teacher/member, plus the owning center's manager on managed groups. Manager update is limited-key (`studentIds/teacherId/teacherName/title/description/targetBand/updatedAt`) — `centerId/classId/managed/joinCode` are client-immutable; teacher writes are personal-groups-only (no centerId either side); managed-group delete is API-only (pair delete keeps attempts). Join-by-code on a managed group → 403 `CENTER_MANAGED`. Subcollection `requests/{autoId}` `{studentId, displayName, username, photoUrl, requestedAt}` — created **only** by `POST /api/ielts/join` (Admin SDK). Subcollection `assignments/{autoId}` — live: `{testId, skill, testTitle, questionCount, totalTimeMinutes, mode, openAt, dueAt, allowedAttempts, resultsVisibility, assignedTo, teacherId, createdAt, status, completedBy[] (server-written)}`.
- **`ielts_reading_tests` / `ielts_listening_tests` / `ielts_writing_tests` / `ielts_speaking_tests` `{test_id}`** — provided doc ID; **public docs are answer-free** (`answers_split: true`, no `correct_answer` anywhere). `teacherId: null` + `source: 'platform'` = admin platform dataset. Platform docs also carry the optional admin **catalog controls** `catalogOrder?: number`, `hiddenFromStudents?: boolean`, `hiddenFromTeachers?: boolean` (2026-07-31, additive; mirrored onto `ielts_test_meta`; missing = visible/unordered). ⚠️ Legacy pre-split reading docs still embed answers until re-saved.
- **`ielts_answer_keys/{testId}`** — `{testId, teacherId, skill, keys}` — the split answer key; owning-teacher-only rules, graded server-side in `/api/ielts/submit`. Never student-readable. Delete allows `resource == null` (legacy tests without a key doc — keeps `deleteIeltsTest`'s batch working).
- **`ielts_test_meta/{testId}`** — library-card summary `{testId, skill, test_title, teacherId, source, test_category?, total_questions, total_time_minutes, typeBreakdown?, createdAt, updatedAt}` **+ `catalogOrder?`/`hiddenFromStudents?`/`hiddenFromTeachers?`** (admin-only, mirrored from the test doc), written in the same batch as every test save. Answer-free; read `isAuth()`; ownership mirrors the test banks. Readers fall back to full-doc fetch when a `getCountFromServer` count exceeds the metas (legacy tests). ⚠️ The catalog fields must be **carried across a re-save** (`carryCatalog` in `services/ieltsService.ts`) — the builders never send them, and a plain `set()` would wipe the admin's ordering.
- **`ielts_ai_usage/{uid}_{YYYY-MM-DD}`** — per-day counter for `/api/ielts/analyze-writing` (`{count, userId, date}`, UTC key). Admin-SDK only — no client rules (default deny).
- **`ielts_attempts/{id}`** — LIVE, **server-written only** (client `create: false`); assignment attempts use deterministic id `{uid}_{groupId}_{assignmentId}` + `attemptsTaken` increment; practice attempts auto-id with `kind:'practice'`. Teacher may update only `reviewStatus`+`teacherGrade` (writing/speaking grading; `teacherGrade.criteria {ta,cc,lr,gra}` optional). `aiEstimate {band, criteria, feedback{uz,ru,en}, model, createdAt}` is written only by `/api/ielts/analyze-writing` (Admin SDK) — additive, advisory.
- ⚠️ **`ielts_tests` does not exist** (dead name; rules block removed).

- **`student_mistakes/{studentId}_{slotKey}`** — 🟢 "My Mistakes" (2026-09-16, [MISTAKES.md](MISTAKES.md)). The student's PRIVATE bucket of questions they got wrong or left blank, fed at submit by the SAT / Milliy sertifikat / Rasch runners. `{id, studentId, slotKey, questionId, source ('sat-math'|'sat-english'|'milliy'|'rasch'), outcome ('wrong'|'blank'), testId, testTitle, question/stem?/imageUrl?/optionKeys[]/options{}/answer/explanation?/examLang (a full question SNAPSHOT — the paper may be edited or deleted), subjectId/subjectName/topicId/topicName/subtopicId/subtopicName/difficultyId (for the "5 similar" lookup; subtopicId is '' for SAT, whose items carry only a domain), timesWrong, lastMissedAt (epoch ms), resolved, resolvedAt?}`. ⚠️ `slotKey` may be `${questionId}#${partId}` for a `shared_options` sub-question (`examSlotKeys`), which is why the doc id is NOT parsed to find the owner — both rule branches compare the `studentId` field. ⚠️ Rules make it readable/writable ONLY by that student — **not** their teacher or centre manager (deliberate: the teacher already has the authoritative outcomes in the result collections). Writer: the student's own client, `services/mistakeService.ts`, via `setDoc(merge)` + `increment` so a repeat updates instead of duplicating. Index: `studentId + resolved + lastMissedAt desc`.

## Leaderboards, library, AI, misc

- **`leaderboards/{periodId}/users/{uid}`** — periods `day_YYYY_MM_DD` / `week_YYYY_WW` / `month_YYYY_MM` / `all_time` (UTC). `{uid, displayName, avatar, classId, xp: increment, lastActive}` merge-set. ⚠️ `getPeriodIds()` is copy-pasted in 3 files — keep identical.
- **`online_books/{bookId}`** — bulk-managed catalog. ⚠️ counters are lowercase `viewscount`/`downloadscount`; incremented on every click (non-unique). `description{en,uz,ru}`, `parts[]` with `telegramLink`.
- **`ai_sessions/{sess_${Date.now()}}`** — teacher analytics chats `{teacherId, title, createdAt (ISO), messages[]}`.
- **`ai_usage/{userId}_{YYYY-MM-DD}`** — `{count, userId, date}` (UTC date key). Writer: **admin** (`app/api/analyze/route.ts`). Rules are `read, write: if false` — no client may touch it. ⚠️ Was previously written by the *client* SDK inside that server route with world-open rules, so anyone could zero their own counter; don't reintroduce a client-SDK write here. Distinct from `users.usage.aiQuestionsUsed`.
- **`notifications/{autoId}`** — `{userId, type (assignment|request|levelup|general), title, message, link|null, read:false, createdAt (serverTimestamp)}` — the union matches the real emitters (AssignTestModal, follow, lib/xp.ts level-up); older docs may carry retired types (submission/result/alert/attendance) and render the default icon. Index userId+createdAt, userId+read. Cross-user creates are legitimate (a submission notifies the teacher; `lib/social.ts` notifies the followee), so rules can't require `userId == auth.uid`. ⚠️ Instead, rules force `read == false` at create and require `link` to be a **relative in-app path** — an absolute or `//host` URL here is an in-app phishing vector, since the link renders as trusted chrome.
- **`active_games/{4-digit code}`** — checkers realtime; `board` is a JSON **string**; `{host, guest, status, turn, winner, mustJumpPiece, moveCount, forfeitedBy?}`. Guest join is transactional (`guest==null` asserted); rooms are deleted on exit-to-menu after the game ends and on account deletion (tab-close can still leak one).
- **`parent_links/{token}`** — 🔐 **account-free PARENT access by QR** (2026-08-03, [PARENTS.md](PARENTS.md)). ⚠️ **The document ID *is* the parent's credential** — 24 chars from a 29-char unambiguous alphabet (≈117 bits), generated with `crypto.getRandomValues`. `{token, centerId, studentId, studentName, label, status:'active'|'revoked', scope:{results,levels,attendance,finance}, createdAt (epoch ms), createdBy, revokedAt?, lastViewedAt?, viewCount, deviceHash?, claimedAt?, claimedDevice?}`. ⚠️ **One child ⇒ one connected person**, enforced twice: issuing a link revokes that student's other active ones in the same batch, and the FIRST browser to open it **claims** it — `deviceHash` is the sha256 of a secret the server mints once and the browser keeps, so every other device gets 409. `claimed*` are absent until the first open and are removed again by `PATCH {unbind:true}` (`FieldValue.delete()`), which lets the same printed QR be re-claimed by a new phone. Writer: **Admin SDK only** — `/api/manager/parent-links[/{token}]` (manager, `requireActiveCenterManager`) and the view-counter bump in `/api/parent/{token}`. Rules: **`read, write: if false` for every client** (section 1.6) — a parent has no Firebase account, so no rule could authorize them anyway, and a browser that could `list` this collection would hold every family's link in the center. Queried by `centerId ==` (+ optional `studentId ==`), sorted in memory — **no composite index**. ⚠️ The token is stored in PLAINTEXT on purpose, same call as `center_*_credentials`: the manager must be able to re-print the same QR, and a hash would kill every card already handed out. ⚠️ `studentId`/`centerId` are never patchable — re-pointing a live QR at another child would show one family another's report on a link they already hold.
- **`parents/{uid}`** — ⚠️ **legacy/unused**: referenced only by the rules helper `isParentOf` (`children[]`); no app code reads/writes it. It is an account-BASED parent model that was never built — the parent feature that shipped is `parent_links` above. Don't confuse the two.
- **`appConfig/androidStudent`** — the native Android student app's update gate; the web never reads it. `{latestVersionCode, minRequiredVersionCode, blockedVersionCodes?[], storeUrl?, message?{uz,ru,en}}`. Rules: public read (checked pre-auth on app start), `write: if false` (edit via console / super admin). Below `minRequiredVersionCode` (or listed in `blockedVersionCodes`) the app hard-blocks until updated; below `latestVersionCode` it shows a dismissible update dialog. Bump `latestVersionCode` on every Play release; raise `minRequiredVersionCode` only for breaking releases.

## Composite indexes (`firestore.indexes.json` — 52, all collection-scope)

**The file is now the full mirror of what is live in Firebase.** It used to list only 13→20 indexes while 27 more had been created ad-hoc in the console, so every `deploy --only firestore:indexes` prompted *"Would you like to delete these indexes?"* — one careless **yes** would have dropped indexes that production queries depend on, breaking them with FAILED_PRECONDITION. The file was regenerated from `firebase firestore:indexes` (verified as a strict superset: all 20 previous entries retained, 27 adopted).

One `fieldOverrides` entry: `requests.studentId` gets a COLLECTION_GROUP index (the account-deletion API sweeps pending join requests with a collection-group query). Counts by collection: `questions1` 10 · `users` 6 · `teacher_questions` 6 (incl. `subject.id`+`createdAt` and `subject.id`+`rand` for the exam draw) · `center_charges`/`center_payments` 3 each · `attempts` 4 · `center_attendance`/`center_staff_attendance`/`custom_tests`/`materials` 2 each · `ai_sessions`, `assignments`, `bsb_chsb_tests`, `center_expenses`, `center_student_finance`, `classes`, `created_questions`, `ielts_groups`, `notifications`, `online_books`, `rooms`, `rush_attempts`, `teacher_rasch_quizzes` 1 each. ⚠️ `created_questions` is a **dead** interim collection (nothing queries it — only historical comments in `lib/questionSchema.ts` mention the shape); its index existed only in the console and was adopted into the file on 2026-07-28 to stop the delete prompt re-arming. Do not treat it as reachable.

⚠️ **Create indexes in the file, not the console.** A console-created index drifts out of the file and re-arms the delete prompt. If you hit a FAILED_PRECONDITION error, add the index to `firestore.indexes.json` and deploy. If someone *does* create one in the console, re-sync with `npx firebase-tools firestore:indexes --project scanqr-64512 > firestore.indexes.json`. Many of the 50 (notably the 10 `questions1` permutations and 6 `users` ones) predate the file and may be unused — do not prune them without checking the query that needs them; the entries carry an explicit `__name__` tie-breaker exactly as Firebase reports them.

Deploy: `npx firebase-tools deploy --only firestore:rules,firestore:indexes` (project `scanqr-64512`). ⚠️ `firebase.json` contains a `functions` block but there is **no `functions/` dir** — a bare `firebase deploy` fails at the functions predeploy; always use `--only`.
